1. INTRODUCTION OF THE PROJECT

FoodRescue is a full-stack web-based platform designed to bridge the gap between commercial surplus food generators—such as college mess facilities, institutional canteens, banquet halls, restaurants, and caterers—and verified Non-Governmental Organizations (NGOs) and community shelters feeding people in need.

Every day, enormous volumes of wholesome, freshly prepared food are discarded simply because of unpredictable footfall, planned banquet buffers, or administrative surplus. Simultaneously, nearby orphanages, shelter homes, and daily-wage colonies face chronic nutritional deficits. The primary bottleneck is the lack of a real-time, transparent communication channel that can coordinate pickup logistics before food reaches its consumption threshold.

FoodRescue resolves this issue by providing a centralized, role-based platform. Donors can instantly log surplus food listings specifying preparation time, storage instructions (e.g., insulated hot containers, refrigeration), available portions, and mandatory pickup expiry windows. Verified NGOs can search by locality, filter by dietary requirements (Vegetarian vs. Non-Vegetarian), claim needed quantities, and track approval and pickup logistics in real-time.

The application is engineered using a robust, decoupled three-tier architecture featuring a React 19 single-page application frontend, an asynchronous Node.js and Express.js REST API backend, and an ACID-compliant MySQL 8 relational database management system.

Technologies Used:
  1. HTML5: Provides the semantic foundation and accessible structure for all web pages and components.
  2. CSS3: Manages layout, responsive grids, custom green-and-cream design tokens, status badge indicators, and smooth UI micro-animations.
  3. JavaScript (ES6+): Handles client-side application logic, asynchronous promises, local storage sessions, and dynamic event handling.
  4. React.js: Facilitates component-driven declarative UI rendering, custom hooks, and dynamic view synchronization.
  5. React Router DOM: Enables seamless client-side single-page routing and role-based route protection without full-page browser reloads.
  6. Node.js: Serves as the high-throughput, non-blocking asynchronous JavaScript execution environment on the server.
  7. Express.js: Powers the backend REST API endpoints, routing structure, and request/response middleware pipeline.
  8. MySQL 8.0 & mysql2/promise: Provides transactional relational database storage with foreign key constraints, cascading updates, and concurrency management.
  9. Fetch API & Axios: Handles asynchronous HTTP networking between client components and backend endpoints.
  10. Multer: Manages secure multipart form-data image uploads for food verification photos.
Objectives:
  • To develop a responsive, user-friendly platform for real-time surplus food redistribution.
  • To prevent edible food from ending up in municipal landfills by connecting donors with local charities.
  • To provide role-based authentication and specialized dashboards for Donors and NGOs.
  • To enforce food safety and hygiene protocols by recording storage details and strict expiry times.
  • To implement transactional reservation logic ensuring quantities cannot be over-claimed.
  • To eliminate operational intermediaries through direct phone and pickup coordination.
2. LITERATURE SURVEY:

Conventional food donation methods in institutional setups predominantly rely on informal WhatsApp groups, occasional telephone directories, or irregular volunteer drives. While well-intentioned, these manual channels suffer from severe latency: by the time an NGO learns about surplus food, the safe consumption window has often elapsed. Furthermore, there is no verification of storage conditions, leading to potential food safety hazards, nor any mechanism to prevent multiple organizations from arriving for the same limited batch.

Commercial food-tech apps (such as food delivery services) prioritize monetized transactions and express packaging, offering no workflow for non-profit surplus redistribution. Specialized charity initiatives exist in select metropolitan cities, but often mandate complex corporate contracts or centralized warehouse logistics, rendering them inaccessible to everyday college hostels and local canteens.

FoodRescue addresses these shortcomings by deploying a lightweight, hyper-local web architecture. By combining instant listing creation, strict expiry timestamps, transparent portion counts, and direct contact numbers, the platform delivers zero-cost food recovery that can be operated seamlessly by mess staff and local shelter coordinators alike.

3. DESIGN OF THE PROJECT
3.1 System Design:

FoodRescue follows an industry-standard Three-Tier Decoupled Architecture:

  • Presentation Tier (Frontend): Built with React 19 and Vite. Renders interactive components including live food listing cards, search bars, role-based dashboards, and modal dialogs. Client state and authentication tokens are managed securely in browser memory and local storage.
  • Application Tier (Backend API): Built on Node.js and Express.js. Handles business logic, role-guard middleware, password hashing using bcrypt, image upload filtering via Multer, and RESTful routing.
  • Data Tier (Database): Powered by MySQL 8.0. Stores structured relational tables (users, food_listings, and food_requests) linked via enforced foreign keys with automatic cascade integrity.

React components structure the platform into reusable, modular elements. React Router DOM manages navigation across public views (Home, About, Contact), authentication gateways, and role-protected dashboards.

The Node.js and Express backend exposes secure REST endpoints (/api/auth, /api/food, /api/requests). When an NGO initiates a claim, the server executes transactional verification to decrement available quantities in MySQL, guaranteeing that simultaneous requests do not cause race conditions or over-commitment.

3.3 Working of the Project:
  • Step 1 (Authentication): Users register as either a Food Donor (Hostel/Canteen/Caterer) or a verified NGO. The system securely hashes passwords via bcrypt and returns a signed JWT.
  • Step 2 (Surplus Listing): The donor navigates to Add Food, fills out the food title, food category (Veg/Non-Veg), portion count, prepared timestamp, storage guidelines (e.g., heated/refrigerated), safe consumption window, and uploads a verification photograph.
  • Step 3 (Real-Time Availability): The listing is stored in MySQL and immediately published on the public landing page and the protected NGO Dashboard with an active available badge.
  • Step 4 (NGO Discovery & Claim): NGO representatives search listings by location and dietary tags. Clicking Request Food opens a modal specifying required servings and transport message.
  • Step 5 (Approval & Pickup Coordination): The donor reviews the incoming claim on their dashboard and marks it as Accepted. Direct phone communication coordinates driver dispatch. Once collected, the status transitions to Claimed/Completed.

5. CONCLUSION

FoodRescue establishes an effective, scalable, and socially transformative solution to the dual crises of institutional food waste and community hunger. By leveraging modern full-stack web technologies, the platform transforms what was previously an uncoordinated, error-prone manual process into an automated, transparent redistribution pipeline.

The project successfully demonstrates the integration of a React 19 single-page interface with a responsive, modern design system, seamless client-side routing via React Router DOM, and a hardened Express.js REST API backed by an ACID-compliant MySQL relational database. The implementation of role-based dashboards, secure JWT authorization, transaction-safe quantity decrementing, and photo validation safeguards hygiene and logistical accountability at every step.

In future iterations, the FoodRescue ecosystem can be further augmented with:

  • Google Maps Platform Integration: Automated calculation of optimal transit routes, distance radii, and live driver tracking between donor kitchens and NGO shelters.
  • Automated SMS & WhatsApp Notifications: Real-time messaging alerts powered by Twilio to notify nearby verified NGO volunteers within seconds of a new food posting.
  • IoT Cold-Chain Sensors: Integration with low-cost Bluetooth/Wi-Fi temperature sensors to monitor food storage safety continuously until delivery.
  • Volunteer Dispatch Network: Crowdsourced delivery coordination allowing registered student volunteers to handle transport for small-batch donations.

Overall, the project provided invaluable practical experience across the entire web application development lifecycle, illustrating how technology can be directly channeled toward humanitarian and environmental sustainability.
